# 双端统一视频库

本入口按作品 ID 分配任务，保留每张 Excel 的原始行属性。NAS 是索引数据库的写入端，Mac 不通过 SMB 打开 SQLite。原有批量入口继续按表输出；不要和本入口同时运行同一批作品。

## 存储与索引

- `媒体库/视频-作品ID.mp4`、`媒体库/图文-作品ID.mp4`：集中存放新素材，不按作品建子目录。
- `来源表/来源分类/原文件.xlsx`：源表副本。`source_rows` 保留来源、工作表、行号和属性；同名表按来源区分。
- `索引/library.sqlite3`：作品、任务、素材位置、内容哈希、来源关联、分析缓存。不得从两台机器通过 SMB 并发写库。
- `任务/`：维护记录；`分析结果/`：后续分析产物；`临时/`：尚未确认入库的传输文件。
- 旧库素材通过 `storage_root + relative_path` 引用，不复制。使用前检查媒体信息、时长和 SHA-256；路径失效或校验异常则暂缓，不当作缺失作品重新下载。
- 内容分析缓存由内容 SHA-256、处理器和配置哈希共同标识。作品属性继续通过来源表关联，不和素材文件去重一起丢弃。

## 初始化

在仓库根目录使用 `uv run python -m app.library_import --root <准备目录> --source <来源目录1> --source <来源目录2>`，导入只允许空任务库。准备完成后，在服务未启动时将整个准备目录传到目标 NAS 目录。

`--inventory <文件清单> --root-prefixes <JSON映射>` 可以登记已有素材候选。清单是每行“字节数、制表符、NAS路径”，仅收录规范命名的正式 MP4，排除回收站。

任务等量分给 `mac`、`nas`，同时近似平衡源表总时长。每台运行两个独立浏览器进程（工作槽 `mac-1`、`mac-2`、`nas-1`、`nas-2`）。任务必须先领取租约，心跳每30秒续租，过期回收；过期租约不能提交文件。元数据模式每槽最多两条在途任务，一个线程解析，另一个线程顺序下载、校验并入库；浏览器始终只在原线程运行。队列中的任务也续租，退出时等待在途任务结束。

## 服务与工作进程

服务：`uv run python -m app.library_api --root <NAS库路径> --roots-file <旧库根目录映射.json> --token-file <私有令牌文件> --host <监听地址> --port 8013 --ssl-cert <证书> --ssl-key <私钥>`。

每个槽独立运行：`uv run python -m app.library_worker --url <服务HTTPS地址> --token-file <令牌文件> --ca-file <证书> --worker <槽名> --scratch <独立本机临时目录> --shared-root <库的挂载路径> --reset-seconds 1800`。

本次 NAS 与 Mac 均使用 `--engine metadata`，复用灰豚元数据下载入口；默认的 `browser` 入口仍可用于独立验证。两者均在入库前校验媒体类型、画面、音轨、源表时长和传输校验和。

metadata 浏览器由可复用的独立子进程持有，单作品解析总时限90秒，包含初始化和所有页面回退。超时会回收该解析进程及浏览器子进程，将本作品记录为可重试的浏览器异常，并继续后续任务；文件下载、校验、提交和心跳仍在工作槽主进程运行，不受解析回收影响。浏览器退出本身也有时限。依赖 `psutil` 清理完整进程树（包括 Chromium 自建的进程组），升级现有容器需安装该依赖。

`--shared-root` 下必须有 `索引/library-id`，当前实例标记为 `douyin-library-20261107`。Mac 先在本机下载，再写入 SMB 的 `临时` 目录；NAS 校验完成后原子移入媒体库，并确认索引已登记。确认成功后才删除本机副本。任务调度、心跳和提交确认通过 HTTPS 进行，视频文件走挂载目录。

## 冷却、cookies 与临时文件

- Mac 的两个槽共享 Mac 冷却；NAS 的两个槽共享 NAS 冷却。两台互不影响。冷却只暂停新远程解析，旧库校验和已下载文件入库继续执行。
- 存在新远程任务时，按9条新任务配1条到期重试调度；无新任务时继续清空到期重试。权限受限作品至少延后6小时复查。旧库和本机完整文件走独立本地队列，不占此配额。
- 每槽解析完成后间隔至少3秒，同一主机的两个解析器领取远程任务也间隔至少3秒；传输并行不会无限预取元数据。
- 每30分钟在当前任务结束后关闭工作浏览器、丢弃临时浏览器缓存并清空工作 cookies；遇到挑战页时也立即重置工作会话，再按本机冷却时间等待。单个作品权限/空详情错误仅关闭该页面、复用浏览器上下文；连续元数据缺失达到冷却阈值、挑战或浏览器异常才重置。原始账号池不删除，不重新导入旧 cookies。验证码仍可能出现，失败任务保留错误和重试状态。
- 未成功入库的完整本机文件暂时保留，并登记所属工作槽，其他槽不重新下载；损坏文件和未完成残留清理。临时待上传积压超过64GiB或本机剩余不足20GiB时暂停新增远程任务，本地待入库文件仍可继续处理。
- NAS 每30分钟清理失去有效租约的传输暂存文件，活跃任务不清理。NAS 原生文件操作清理传输失败残留，避免 Mac 经 SMB 删除产生反复回收副本。
- 五次失败后转入 `needs_review`，不假报成功或永久删除。
- 连续三次未捕获元数据时，对发生异常的主机冷却5分钟；持续异常逐步延长到15分钟。该类无响应不消耗作品重试次数，远程解析成功后清零连续失败计数；本地复用/入库成功不清零，避免误报解析恢复。达到冷却阈值时工作浏览器重置。权限限制等明确作品级错误仍按原重试规则处理。

## 查询与维护

携带 `Authorization: Bearer <令牌>` 访问 `/status` 查看两端进度、所有在途任务和冷却剩余秒数（`scheduler_version=2`），访问 `/works/<作品ID>` 查看素材、NAS路径和全部来源记录。不要在日志中打印令牌或 cookies。

目录迁移必须先停止索引服务和涉及的工作槽。`uv run python -m app.library_admin flatten --root <NAS库路径>` 将早期哈希分桶布局改为集中命名，先校验哈希，再记录迁移清单并更新索引；不改变素材内容或素材 ID。

Mac 运行使用 LaunchAgent，运行期间由 `caffeinate -i` 防止空闲睡眠。合盖、断网、退出登录仍会影响 Mac 任务；NAS 可继续运行。停止 Mac 时卸载对应 LaunchAgent，停止 NAS 时停止对应工作容器；不要直接删除索引。

维护升级时可在库的 `任务/pause-claims` 放置标记暂停所有新领取，在途任务继续续租和提交；完成切换后删除标记恢复。单个新版本工作进程可在其 scratch 目录放置 `drain` 标记，或发送 SIGTERM/SIGINT，等待队列完成后退出。Mac 当前由终端 supervisor 管理，停止子进程会在30秒后自动重启；维护时先暂停领取。

当前 NAS 工作容器共享协调服务的网络命名空间，使用 `https://127.0.0.1:8013`。重启 `douyin-library` 后，需在 NAS 在途任务处理完毕时依次重启两个 NAS 工作容器以重新加入网络；确认恢复领取与入库，不能仅以容器仍在运行判断连接正常。

# 2026-10 批量下载稳定性改动与 Windows 同步

对比基线：GitHub `main` 的 `eecc985`。本次将 macOS 与 NAS 长任务中使用的通用修复纳入仓库，并保留主分支后续更新。

## 稳定性来自哪些变化

| 原行为/问题 | 本次变化 | 作用 |
|---|---|---|
| 独立脚本写死 Windows 用户目录、嵌套虚拟环境和验证视频 | 输入输出、会话、代理可传参；三个平台共用模块；启动脚本从仓库根目录运行 | Windows 可使用同一套下载逻辑，迁移目录不必改源码 |
| 旧登录 Cookie 可能使作品直达页不可用 | 增加显式独立访客模式，拒绝混入登录凭据；登录模式可复制指定账号会话 | 可选择经验证可用的访问方式，原账号池不受改动 |
| 浏览器播放器通过 fetch/XHR 预加载媒体 | 按请求类型、CDN 域名及媒体路径拦截；捕获详情后关闭页面，复用浏览器上下文 | 降低额外流量和浏览器负担 |
| 解析与下载代理行为不一致 | 登录、人工验证、解析共用代理参数；文件 HTTP 客户端忽略环境代理 | 避免应用层代理混用；操作系统 TUN 仍须用户自行关闭或配置分流 |
| 风控后的等待和会话保存不可靠 | 有界冷却重试，检测人工更新会话；验证成功才保存；忽略正常页面的隐藏验证码 iframe | 避免无限等待、误报验证及关闭窗口时覆盖有效会话 |
| 权限限制被当成永久删除 | 区分明确删除与权限/隐私/登录限制，旧误标记录可重新解析 | 可重试失败不再被永久漏掉 |
| 有失败或仅试跑也写整表完成标记 | 续跑核对物理文件和 manifest，不盲信旧完成标记；失败通过退出码反馈 | 同一命令能够补跑失败或缺失文件，不把“处理完”当“全成功” |
| 共享盘下载中断、EBUSY/EINVAL、临时文件句柄失效 | 视频先在本地完成，再经独立 UUID 临时文件发布；短暂存储错误有限重试；manifest 同样原子替换 | 减少半成品暴露，避免重用失效 SMB 句柄 |
| manifest 读取异常后退回空记录 | 无法读取或 JSON 损坏时停止，保留原记录 | 防止覆盖已有进度；持续断网仍需恢复连接后续跑 |
| NAS/本地浏览器依赖漂移 | Playwright 固定为 1.64.0，NAS 镜像包含独立批量脚本，提供基于现有镜像的离线更新 Dockerfile | 减少部署版本差异；离线更新基镜像仍须有匹配的 Chromium |
| Windows 优先下载脚本另维护旧版下载与进度逻辑 | 优先表改用公共批量入口，保留目标目录，单表串行，失败最多补一轮 | 避免旧完成标记、删除误判和冷却接口差异重新引入问题 |

## 运行方式也影响稳定性

当前长任务主要采用 **单表串行、并发 1、每个输出目录只有一个写入者**。NAS 在本机挂载卷内落盘，避免每个媒体块经 Mac 的 SMB 连接传输；Mac 的共享盘写入则依赖网络及挂载持续可用。低并发减少请求峰值，但不能保证解除平台限制。

这次实际运行中，Mac 五表 28006 条最终为 25068 成功、2938 失败；NAS 周榜 33595 条最终为 25323 成功、8272 失败。它们说明任务可以结束、保留结果并补跑，不代表下载成功率为 100%，也不能据此证明某一项改动单独造成成功率提升。

逐表排队、结束后筛选失败子集、精确 ID/文件核验、进程锁和每小时汇报，还使用了本次任务专用的监督脚本。这些脚本位于被忽略的 `tmp/`，包含具体任务、机器路径及运行状态，不随 Git 同步。Windows 获得的是通用下载修复；若需要相同的无人值守队列，需要为 Windows 的输入输出另行配置。不要同时启动两个任务写入同一表目录。

## Windows 更新

先结束 Windows 上旧版本的下载进程，再在原仓库目录执行：

```powershell
git fetch origin
git switch main
git pull --ff-only origin main
.\setup.bat
```

若有未提交修改或分支分叉，先保存并合并自己的改动，不要强制重置。`setup.bat` 同步依赖、安装匹配 Chromium 并检查 FFmpeg；无需安装 ASR。本机浏览器会话和历史输出不会由 Git 同步或覆盖。

推荐使用公共灰豚入口，并明确传入路径（替换示例目录）：

```powershell
uv run python batch_download_huitun.py --source "D:\灰豚数据\榜单.xlsx" -o "D:\视频输出" --dry-run
uv run python batch_download_huitun.py --source "D:\灰豚数据\榜单.xlsx" -o "D:\视频输出" --concurrency 1 --proxy none
```

如已准备独立访客会话，在正式命令追加 `--anonymous-state "D:\会话\guest.json"`。否则使用 Windows 本机有效会话，必要时运行 `扫码登录.bat` 由人扫码。需要人工验证时，验证脚本与下载脚本必须使用相同会话路径和代理参数。切换输出目录会产生另一套结果，续跑应使用原目录。

`download_priority_and_resume.py` 仍保留既有 Windows 优先表路径配置，使用前必须检查 `PRIORITY_TASKS`；新任务优先采用上述公共入口。优先表现在串行处理；其 `--concurrency` 只控制后续多表任务，`--no-resume` 可禁止自动接续默认目录。

## 验证边界

本地使用 `DOUYIN_BROWSER_SMOKE=1 uv run pytest` 验证，包括真实 Chromium 的本地代理/媒体拦截、存储错误注入、断点续跑、会话及跨平台路径测试。仓库 CI 在 Windows、macOS、Linux 上执行同一测试集。Windows 的真实抖音会话、网络和共享盘仍须在目标机器上验证；本地通过不等于 Windows 实机已验证。
